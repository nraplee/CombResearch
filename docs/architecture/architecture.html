What a cloner hits today

  1. No data. About 9 GB lives only on the Ryzen PC; the GitHub clone has none of it except the 104 MB Mac-only .mx files. Everything has to be regenerated, which takes days (q=10 IS) plus 17 h for (4,5) truth.
  2. No single entry point. About 15 scripts run in an order kept in AGENTS.md and people's heads. Configuration is about 30 COMB_* environment variables. Parallel runs need Windows PowerShell.
  3. Manual steps in the chain. McKay truth must be renamed by hand from _truth_mckay.wxf to _truth.wxf. The .tex needs figures copied by hand into an Images/ folder that does not exist, and their names do not match what the renderers write. The Fig 2 notebooks write to their own cwd and need the global paclet.
  4. Two worlds. Fig 2 comes from interactive notebooks; the rest comes from scripts. The ECGrav pin (1.18) differs from the version that made the data (1.17), and the WXF files do not record which version made them.
  5. Clutter. Superseded or one-off files sit beside production ones: run_q10_mh_pilot, precompute_is_histogram, migrate_csv_to_wxf, pure_simplicial_compute_overnight, probe_betre_mx, pure_simplicial_figures.nb, three diagnostic renders, archive/, the tracked logs, and dev-only worktree sync tooling.
  6. Dead outputs. Every *_summary.wxf and merged_complexes is written and never read; L1 tables are transcribed into the docs by hand.

See inventory.md for every per-file issue, plus the critic's cross-checks.

Ideal architecture

Revised 2026-11-20 for the project direction:

  • always run on the latest upstream ECGrav (Dr. Betre's main branch);
  • the algorithms here should eventually be merged into ECGrav;
  • data is not published, so a reproducer regenerates it;
  • LaTeX lives on Overleaf, and local .tex files are reference only.

The goal: an outside researcher clones the repo, installs Wolfram 15+, and regenerates the data and figures with one command. We keep working the way we do now: worktrees, one shared data store, long parallel runs on the Ryzen.

Developer guarantees (hold after every phase)

  1. One output root, decided in one place. - comb_paths.wl / .ps1 keep the git-common-dir logic, which lets worktrees share outputs. A plain clone resolves to itself (checked: git -C src rev-parse --git-common-dir gives ../.git). - A repo-marker guard handles a zip unpacked inside another repo: the git root is accepted only if it contains src/comb_paths.wl, otherwise the code checkout is used. COMB_ROOT still overrides. - $CombResultsDir is added, and results joins the sync script's folder list.
  2. Existing data stays valid and is never rerun by accident. - No phase renames or moves existing WXFs. One naming helper produces today's flat names. - An output with no manifest counts as up to date and is rerun only with --force. --force covers only the stage and cells named on the command line, never all. - Outputs made with an older ECGrav commit are reported as stale, not rerun automatically.
  3. Bare scripts behave exactly as today. - With no --profile and no COMB_PROFILE, settings resolve to each script's current defaults. For example, enumerate_truth.wl keeps its 5 cells and the cheap pipeline, so it never OOMs on (4,5). - Order: CLI flag, then COMB_* env, then named profile, then script default. run.wl prints each setting with its source and warns when a leftover env var overrides a named profile. - Every existing COMB_* knob keeps its name. AGENTS.md maps --cells to each stage's own knob (COMB_TRUTH_CELLS, COMB_MH_CELLS, COMB_ECG_CELLS, COMB_VAL_CELLS, COMB_IS_CELLS, and p-only COMB_CMP_PS).
  4. Old entry points keep working until their replacement is proven. A folded script becomes a shim that Gets the new code *in the same kernel*. That preserves the *Override protocol: run_p3.wl:4-10 sets pListOverride and sampleSizeOverride before Getting pure_simplicial_compute.wl. Shims go only in Phase 5.
  5.
